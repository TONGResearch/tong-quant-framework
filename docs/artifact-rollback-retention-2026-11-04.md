# 共享原文的回滚保留策略

日期：2026-11-04，马来西亚时间。WP-LAUNCH-001，ready / not accepted。

## 复现的问题

原文采用内容寻址并可由多个进程／数据库共用。原先 StoredProviderArtifact.created
为 true 时，FileSystemArtifactStore.discard 在入库回滚后按哈希删除文件。
created 仅说明该次 put 发布了路径，不能证明该文件仍由该进程独占。

临时合成实验复现：A 首次写入 -> B 复用相同路径 -> A 回滚 -> B 原文被删。
原实现得到 first_created=true、second_reused=true、survive=false。
没有使用或损坏真实用户原文。新增测试还覆盖 B 已真实提交 SQLite 登记后再回滚 A，
同库／异库共享，以及另一个独立 Python 进程提交。

## 本轮修复

FileSystemArtifactStore.discard 保留接口但不再删除任何已发布原文。
ProviderArtifactStore 的契约明确：放弃一次尝试，不得误删别的写入者可能已采用的字节。
StoredProviderArtifact.created 保留原义，不再作为删除租约。
并发共享不通过不完整的本库引用查询来猜测安全删除，因为另一个数据库也可能引用它。

失败仍向调用者报告；batch、证据与关联仍按原事务回滚。失败库未登记的字节保留待核查，
不生成伪 batch、虚构成功记录、重写原文时间／哈希或提升信任／可用时间精度。
在失败库未登记不等于全局无主；另一数据库可能已经采用它。
多文件留存中途失败，已发布的字节同样保留；未发布的本次私有临时文件仍按原逻辑清理。
既有文件、同内容重复调用、已被替换为符号链接的路径，都不在回滚时删除或追踪写入。
读取／已登记文件审计仍独立拒绝坏哈希、缺失文件及不安全符号链接。

## 代价与边界

- 回滚可能留下未登记原文；文件存在不代表数据留存成功，更不是研究、PIT 或交易准入。
- 当前审计只核对一个数据库登记的原文，不清点全部未登记文件，也不能证明全局无引用。
  审计全部登记项通过时，仍不能声称完整原文目录或所有数据库都已备份／对账。
- 暂不实现自动垃圾回收、TTL、直接删除或所谓“本库查不到就删”。未来删除必须具备
  覆盖全部相关数据库的引用证据、在途写入隔离、保留／授权政策及独立审查。
- 这是以磁盘占用换取原文不被误删的保护。无人值守采集前须核定空间预算、告警、
  有界采集／重试和保留政策；保留并不意味着可以无限增长或无限保留许可受限内容。
- 数据库事务与文件发布仍不是跨资源原子事务，断电后的目录项持久性、完整原文盘点、
  精确任务对账、加密共保留和异机恢复仍需独立核验。未补完就不启用自动采集。
