## 为什么不能直接扩展旧 ingestion batch

旧批次在 fetch／校验后创建，没有任务身份、代次、预采集尝试或租约；COMPLETED
也可表示失败快照留存成功。不能拿 batch 终态当成任务完成，也不能用 plan_hash
同时代表计划、实际数据可用时点、任务幂等键和响应哈希。

## 建议增加两张表

| 表 | 不可变身份／范围 | 运行／审计字段与约束 |
| --- | --- | --- |
| refresh_jobs | job_id 主键；plan_hash、scope_hash、显式 trigger_reference 的唯一组合；完整规范化 scope／请求类型／配置／版本快照和各自哈希 | status、generation、row_version、next_eligible_at、created_at、updated_at；策略预算固定，不能续跑时放大次数；无交易／授权字段 |
| refresh_attempts | (job_id, generation) 主键，job_id 外键；公开随机 lease_nonce 唯一；worker_id；固定尝试策略与模型版本 | phase、status、claimed_at、lease_expires_at、retention_started_at、updated_at、captured_payload_hash 可空、ingestion_batch_id 可空且唯一、failure_code 可空；batch 外键指向 ingestion_batches，禁止删除已引用记录 |

索引：jobs 的状态／下次可用时间；attempts 的状态／租约到期。
每个 job 只能有一条 RUNNING 尝试（部分唯一索引）。字段有 CHECK／长度／枚举
约束；重建还须运行 Python 契约校验。所有 UTC 字段使用统一的精确序列化，
数据库比较前须规范化，不能直接比较带不同时区偏移的字符串。
敏感字段／内容仍在仓库层拒绝；配置快照绝不包括环境凭据或原始异常。

job_id 由规范化 plan_hash＋scope_hash＋显式触发身份派生；相同请求重登记返回
原任务，不同内容同主键须拒绝。重试增加 generation／nonce，保留原尝试，不创建
新任务抹去失败史。另一轮合法观察有新的触发身份，不能把同字节响应当成没采过。
Git commit／dirty 位不能认证代码；部署前仍需审查过的代码／配置内容基线。

## 必需事务边界

1. **登记／领取**：核验计划和不可变范围；短事务内对 job 的 row_version、状态、
   generation、预算、时间做 CAS，插入尝试并更新 job。失去竞态者不调用提供商。
   任务和尝试开始先提交，再进行任何网络调用；网络等待不持有写事务。
2. **开始留存**：短事务校验当前 generation／worker／nonce／有效租约，保存
   RETAINING、实际捕获内容哈希及开始时间。未知响应保持空，不伪造哈希。
3. **数据与关联**：在现有 ingestion 留存事务内原子写入 batch、证据、原文登记、
   attempt 的 batch 关联及待对账状态；同事务重新核对当前归属、租约和版本。
   需要一个**明确类型化的 refresh attempt 关联参数**及仓库契约；现有接口尚无此
   功能。不能用 write_canonical 做泛化调度钩子、改严格提供商参数，或在提交后
   再用另一事务补关联。否则“已入库但无关联”的崩溃窗口仍无法可靠消除。
4. **核验／检查点**：只读取该任务／尝试的精确关联，核对真实 batch、原文及
   哈希、来源、数量、输出状态和警告，再以当前代次／版本提交留存进度。
   失败快照／空输出记录单独结果，不能标成可用数据或推进成功数据检查点。
   留存进度完成仍不是研究、PIT、最新披露或策略准入。

Provider 接口保持原边界。未来 worker 先按显式桥接完成有界捕获，再把已捕获值
交给相应证据适配器；不假设任何 adapter.fetch 都不联网。AKShare 的旧采集、
Yahoo 快照与原文流程分别验收，不因静态请求通过就宣称已有四市场更新器。

## 崩溃、失联与恢复

- 任一租约过期均进入待对账，不直接抢跑；未记录 capture 不证明没有响应／提交。
- 精确关联已提交：验证留存和原文，保留延迟／失败／未知信息，不重复创建数据。
  精确关联未提交：须确认过期和旧进程已被事务代次隔离，才在预算内安排新尝试。
  关联损坏、缺失原文或存在孤立 batch：暂停并报告，不能凭证券与时间范围猜关联。
- 如果数据库／文件系统写入失败，先保留可审计状态再恢复；过期工作进程的迟到
  数据不能覆盖后续尝试。不同进程共享的内容寻址原文必须有安全的登记／清理协议，
  不能因一个事务回滚删除另一事务已采用的字节；需要并发故障注入验收。
- 永久失败停止自动重试；临时明确采集失败按固定预算退避；留存失败或未知提交
  必须对账。原始异常、认证 URL、Cookie、令牌不得进入表或日志。
- 实际捕获时间由真实操作取得；计划时间与测试时钟不得倒填 available_at。
