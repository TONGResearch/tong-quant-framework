## 目标与边界

面向明确声明的自选股／研究候选，自动发现新数据、采集、校验、保留版本，
再生成待更新的研究输入。正常运行不依赖 Tong 每天手动下载 K 线或录入财报。
本方案不承诺全市场、实时行情、完整历史或自动解释所有财报。

自动更新数据，不等于自动修改投资策略、批准来源、改变评分权重或执行交易。
PIT 仍为 UNSUITABLE；真实资金、券商下单、资产配置继续冻结。
现有执行和通知默认关闭；不会为数据更新开启 Notification Engine。

### 最初复现的调度前置缺口（历史演练）

ProviderNeutralIngestionService 在 adapter.fetch 返回并通过校验之后，才创建
已完成的 ingestion_batches 记录。一次本地临时数据库、假下载器的异常演练确认：
fetch 抛出异常时，批次数和证据数均为零；未联网，未使用用户数据库。

这是**自动调度所缺少的尝试审计**，不是原子入库失败或已有数据被污染。
带 refresh_lease 的新路径现已补充采集前持久尝试；未带租约的旧调用仍有该缺口。
ingestion_batches 虽有 RUNNING／FAILED／RETRYING 和 retry_of 字段，不能据此
声称通用采集已经具备持久运行记录、崩溃恢复或租约管理。
适配器返回的失败快照也可能被成功留存为 COMPLETED 批次：
**留存成功不代表提供商可用、数据完整或研究成功。**

## 最小实施结构

```text
显式股票池与数据范围
  → 更新计划器（只读、无联网）
  → 持久任务／尝试账本（先记录，再采集）
  → 受限数据采集器（复用现有 Provider／入库边界）
  → 校验与版本留存／隔离
  → 受影响研究输入清单
  → 经独立准入后，才重新评估正式研究
```

研究、筛选、投资评分和验证接口不倒置依赖于调度器。采集器不导入或调用
Execution／Broker／Order／Trade／Fill／Paper Trading／Portfolio。
调度不能把接口探测、失败快照或重复同源观测当成独立校准。

## 更新计划契约

计划必须固定：股票池版本与哈希、证券身份／市场／币种、数据集与提供商能力版本、
请求窗口、实际决策时点、配置哈希、框架版本、Git 提交和未提交状态。
Git 提交不能单独代表当前脏工作区；生产部署前须有审查过的代码基线。
股票池是研究范围，不是持仓、推荐或资产分配。

| 数据 | V1 更新触发 | 缺口处理 |
| --- | --- | --- |
| 日 K 线／成交量 | 使用已批准交易日历与阶段证据，针对已结束会话增量更新；重叠窗口用于发现修订，长度须显式配置 | 日历／会话不明确时标 UNKNOWN，不猜周末、收盘、节假日或最后一根 K 线完整性。 |
| 基本面／财报 | 对已支持目录做有界检查；新原文／新快照保留独立版本 | 年度数据不是最新季报；未知发布／修订时间不回填，不把“没发现”解释为无新公告。 |
| 证券生命周期／公司行为 | 每次形成当前研究包前检查已声明支持范围 | 空结果不代表正常上市、无停牌或无分红；ST／退市／停牌记录不消失。 |
| 新闻／政策 | 保留将来接入点，按提供商授权独立验收 | V1 不伪装已有完整新闻流，也不让 AI 自动批准指标或交易。 |

不先硬编码四市场同一个北京时间／UTC“收盘任务”。美股夏令时、交易所假期、
半日市、临时停市与会话阶段须来自相应已核定契约。日历未准入时仍可保留
明确请求的原始探索性快照，但不得标为“完整已收盘数据”或授权后续判断。

数据窗口的日历口径与 PIT 可见时间分开：任务原定时间不是实际可用时间。
复用现有下载后固定实际 captured_at 的方式，不能为通过未来数据检查而倒填
available_at、冻结旧时钟或放宽校验。抓取同一旧文件不使报告期间变新。

## 尝试、重试与一致性

拟议的任务身份由计划／数据范围／窗口／触发序号组成；**不是只用证券代码**。
重试沿用任务身份，新增 attempt；租约所有者、到期、尝试次数和退避均需持久化。
下一次计划运行可产生新观察，不能因为内容字节相同就抹去实际获取时间。

- 每次网络调用前先保存尝试开始状态。进程退出后租约到期可恢复，旧工作进程
  不得在租约失效后覆盖新状态；需要领取代次／隔离标记和测试。
  网络等待不持有 SQLite 写事务。没有响应的尝试保留缺失响应／哈希，不能以
  零哈希或异常文本哈希冒充真实提供商响应。
- 区分权限不足、限流／临时不可用、实现／解析缺陷和数据质量不足；只保存安全
  错误码，不保存原始异常、令牌、Cookie、认证 URL 或邮箱请求头。
- 永久失败进入可审计终态；不无限重试、不因某个提供商失败就悄悄替换来源。
- 检查点仅在证据／原文／批次完成并验证关联后推进。留存了失败快照，应记录
  “失败快照已保存”，不能报告“数据已更新可用”。
- 单只／单数据集失败不能让其他股票被伪报成功；汇总保留每项失败和遗漏。
- 崩溃发生在证据提交后、检查点提交前时，先核对已留存批次及原文，恢复关联；
  不重复创建 canonical 数据或默默丢弃旧版本。禁止借用 write_canonical 回调
  充当泛化调度接口，或把任务字段塞进严格提供商请求参数。

### 数据库设计决定

最初方案未改表；之后已实现 refresh_jobs／refresh_attempts 及
ingestion_batches 关联，对应 0011／schema 0.8.3。保留的用户数据库未自动升级。
本次准入设计不新增表、容量预留计数器或迁移；若实施需要新状态／列须另审。
现有批次是数据留存审计，不是可直接复用的持久任务队列。
租约、检查点与入库提交的跨步骤一致性必须有明确实现及故障注入测试，
不能先安装定时器，再用日志补充审计。

## 数据进入研究的规则

自动抓取先形成未准入证据；不自动提升 TrustLevel、AvailabilityPrecision、
PITReadiness 或历史连续性。核对可用时间、证券／币种、期间／单位／集团口径、
来源完整性、时效及提供商冲突后，才生成待研究输入。

原文变动、财报修订、价格修正触发受影响输入／报告清单，旧报告保持原版本，
标明需要重新评估；不能只修改旧报告时间戳。新输入未通过必需检查时暂停相关
正式判断，保留旧报告供审计，但不能把它作为当前有效结论。
自动发现新 PDF 不等于自动准确读取每张表；不支持格式进入待审查队列，
不猜公式、零值、单位、银行监管范围或涨跌停状态。

## 分步交付与验收

1. **只读更新计划**：显式自选股与范围，列出可采集／不支持／权限限制／时效
   缺口及计划身份。无网络、无数据库写入，不声称计划就是更新完成。
2. **一次性受控更新器**：持久尝试、租约、限时、限速、重试、故障恢复、幂等
   检查点与质量门槛。先用 fake provider，再用有权限的真实数据验收。
3. **独立定时部署**：审查股票池、预算、数据授权、目标设备和恢复演练后，
   才启用已验证的一次性更新器。默认 disabled；不依赖 AI 继续对话才推进任务。
4. **研究刷新**：依赖合格输入与已批准方法，连接真实 ResearchQueue／唯一
   ResearchReport／带状态 InvestmentAssessment；不因刷新成功放行评分或交易。

必须覆盖：重复触发、并发领取、租约过期、陈旧工作进程、断电与断网、429、
无权限、解析失败、响应为空、提交后崩溃、配置／代码变化、冬夏令时／假日／
未知日历、半日／未收盘 K 线、复权混入、修订保留、停牌／退市保存、原文丢失、
凭据过滤以及健康来源不能替补失败来源。
部分成功、未知日历和不支持行业必须保留，不得用四个空数据包宣称四市场覆盖。

## Tong 将来的操作与当前需要

正常运行后不需每天手动更新；只处理授权／凭据到期、订阅预算、长期来源冲突、
不支持披露和需要审查的方法变更。机器必须在任务运行时可用；本地休眠／离线
时错过的任务应在恢复后补跑并标明延迟，不能冒充准点获得的数据。
未来换设备同时恢复审查过的代码、加密数据库和外部原文，不能只克隆 Git。

**当前不要求提供密码、令牌或开通新账户。** 本轮没有安装计划任务，没有新增
网络调用，没有自动更新用户数据。后续先实现离线计划与恢复测试；启用定时
服务前再确认自选股、运行位置与访问授权。原有对话跟进任务不被更改或替代。
